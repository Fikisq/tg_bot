# SPEC — сайт «Домены на починку» (папка `front/`)

> Это задание на реализацию. Кода сайта здесь пока нет — создана только
> структура папок, зависимости и мок-данные. Реализацию делать **строго внутри
> `front/`**; файлы вне этой папки не трогать, включая корневой
> `requirements.txt` проекта (у сайта свой — `front/requirements.txt`).

## 1. Что это

FastAPI-приложение для отображения задач на «починку» доменов: пользователи
присылают ссылки в Telegram (бот подключается позже), ссылка сокращается до
домена (`https://www.amd.com/ru/page` → `www.amd.com`), и по каждому домену
внешний скрипт с LLM потом выполняет ремонт. Сайт — **только отображение**:
приём ссылок, скрипт и LLM в этот этап не входят.

Сейчас сайт читает мок-данные из `front/data/tasks.json` и рендерит две
страницы: публичную главную и страницу администратора.

## 2. Запуск

```bash
cd front
pip install -r requirements.txt
uvicorn app:app --port 8000 --reload
```

Точка входа — `front/app.py`, объект FastAPI обязан называться `app`
(запуск именно как `uvicorn app:app` из папки `front/`).
Пути к `templates/`, `static/`, `data/` строить от
`Path(__file__).resolve().parent`, чтобы сайт работал и при запуске из корня
проекта (`uvicorn front.app:app --port 8000 --reload`).

## 5. Модель задачи

`data/tasks.json` — массив объектов:

| Поле        | Тип         | Описание                                              |
|-------------|-------------|-------------------------------------------------------|
| `id`        | int         | уникальный идентификатор                              |
| `url`       | str         | исходная ссылка, как её прислали в Telegram           |
| `domain`    | str         | нормализованный домен (правило — §6)                  |
| `sender`    | str         | отправитель из TG, с `@`                              |
| `status`    | str         | `"in_progress"` \| `"error"` \| `"resolved"`          |
| `message`   | str \| null | пояснение; текст ошибки при `status="error"`          |
| `created_at`| str         | ISO 8601                                              |
| `updated_at`| str         | ISO 8601                                              |

Статусы хранить латиницей, отображать по-русски:
`in_progress` → «В работе», `error` → «Ошибка», `resolved` → «Решено».

## 6. Нормализация url → домен

Оставить только host: схему, path, query и fragment отбросить, регистр —
нижний. Префикс `www.` **сохранять**:
`https://www.amd.com/ru/products?x=1` → `www.amd.com` (не `amd.com`).

Референс:

```python
from urllib.parse import urlsplit

def to_domain(raw: str) -> str:
    raw = raw.strip()
    if "://" not in raw:
        raw = "//" + raw
    netloc = urlsplit(raw).netloc
    host = netloc.split("@")[-1].split(":")[0]  # убрать user:pass@ и :port
    return host.lower()
```

Если host пустой (в строке нет домена) — это ошибка данных: такой таск не
показывать на главной, в админке помечать «Ошибка».

## 7. Страницы

### GET `/` — главная (публичная, «красивые текущие таски»)

- Карточки **активных** тасков (`in_progress` и `error`): крупно `domain`,
  под ним `sender`, цветной бейдж статуса, `updated_at`, исходная ссылка `url`
  мелким моноширинным текстом с обрезкой `text-overflow: ellipsis` и
  `title="<полный url>"`.
- Таски `error` дополнительно показывают `message` (текст ошибки).
- Ниже отдельным компактным блоком «Решено» — список решённых (только домен и
  дата, без карточек).
- Шапка: название сайта + счётчики (всего / в работе / ошибка / решено).
- Сетка карточек: CSS Grid, `repeat(auto-fill, minmax(280px, 1fr))`,
  скругления, лёгкие тени, статусные цвета из §9.

### GET `/admin` — администратор

- Минималистичная таблица: `id`, `domain` (моноширинно), `sender`, бейдж
  статуса, `created_at` / `updated_at`, `message` (если есть — строкой под
  доменом или в тултипе).
- Фильтр по статусу: пилюли «Все · В работе · Ошибка · Решено». Реализация —
  на выбор: query-параметр `?status=` (серверный фильтр) или клиентский JS.
- Сортировка: новые сверху (по `updated_at` DESC).
- Кнопок редактирования **не делать** — статусы будет менять внешний скрипт.
  Авторизации нет (локальный инструмент).

## 8. Маршруты (текущий этап)

- `GET /` → `templates/index.html`
- `GET /admin` → `templates/admin.html`
- Static: `app.mount("/static", StaticFiles(...))` → папка `front/static`.

Будущие эндпоинты (только задел, **не** реализовывать сейчас; упомянуть в
docstring `routers/pages.py`):

- `POST /api/tasks` `{url, sender}` → создать таск (нормализация + `in_progress`)
- `PATCH /api/tasks/{id}` `{status, message}` → обновить статус
- `GET /api/tasks?status=…` → JSON-список

## 9. Дизайн-токены (рекомендация, не догма)

- Статусные цвета: В работе `#3b82f6` (синий), Ошибка `#ef4444` (красный),
  Решено `#22c55e` (зелёный). Бейдж — подложка цвета статуса с прозрачностью
  10–15% и текстом того же цвета.
- Тема: тёмная по умолчанию (фон `#0f1115`, карточки `#171a21`, текст
  `#e5e7eb`) или светлая — на выбор реализации; вся палитра только через CSS
  custom properties в `base.css`.
- Шрифты системные (`system-ui`; домены и url — `ui-monospace`), без внешних
  CDN и веб-шрифтов.
- `base.css` — общее (переменные, reset, шапка, бейджи); `index.css` и
  `admin.css` — только специфичное для своих страниц.

## 10. Чтение данных

- `load_tasks()` в `utils.py` читает `data/tasks.json` **при каждом запросе**
  (кэш не нужен): файл будут обновлять внешние компоненты.
- Файл отсутствует или битый → возвращать `[]` и писать предупреждение в лог
  (loguru уже есть в проекте, но в `front/requirements.txt` его нет —
  использовать стандартный `logging`).
- Сайт ничего не пишет на диск.

## 11. Критерии приёмки

1. `cd front && uvicorn app:app --port 8000 --reload` поднимает сайт без ошибок.
2. `/` рендерит карточки из `data/tasks.json`; домены без схемы и пути
   (`www.amd.com`, а не `https://www.amd.com/...`); исходный url доступен.
3. `/admin` — таблица со всеми тасками, фильтр по статусу, русские подписи.
4. Статусные бейджи трёх цветов, смысл понятен без чтения легенды.
5. Ничего вне `front/` не изменено; зависимости сайта — только
   `front/requirements.txt`.
