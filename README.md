# Telegram VPN Bot

Pet-проект системы регистрации пользователей и выдачи VPN-подписок через Telegram-бота.

В дальнейшем система будет включать backend, сайт, панель администратора и автоматическую обработку сообщений о недоступных сайтах.

> Проект находится на ранней стадии разработки. Сейчас реализована часть функциональности Telegram-бота и прототип интерфейса сайта.

## Цель проекта

Главная цель проекта — изучение и практическое применение:

- базового синтаксиса Python;
- асинхронного программирования;
- работы с HTTP API;
- FastAPI;
- PostgreSQL;
- SQLAlchemy 2.0;
- Linux;

Frontend не является основной целью изучения в этом проекте. Его реализация и дальнейшая доработка будут выполняться преимущественно с помощью нейросетей.

## Идея проекта

Пользователь переходит в Telegram-бота по специальной пригласительной ссылке. После проверки приглашения бот:

1. Регистрирует пользователя в системе.
2. Создаёт клиента в VPN-панели.
3. Получает ссылку на VPN-подписку.
4. Отправляет подписку пользователю.

В будущем вместо обычной ссылки бот также сможет отправлять QR-код.

Пользователь сможет сообщить о проблеме с сайтом:

1. Нажимает кнопку «Проблема».
2. Отправляет URL недоступного сайта.
3. Система нормализует URL до домена.
4. Создаёт задачу на проверку.
5. Задача появляется на сайте и в панели администратора.
6. Серверный скрипт пытается решить проблему автоматически.
7. Если обычный скрипт не справляется, задача передаётся LLM.
8. Результат выполнения сохраняется в PostgreSQL и отображается на сайте.

Пример нормализации URL:

```text
https://www.example.com/some/page?value=1
                     ↓
               www.example.com
```

## Планируемая архитектура

```text
Браузер ──────────┐
Telegram-бот ─────┼──> FastAPI ───> PostgreSQL
VPN worker ───────┘       │
                          └───────> VPN-панель
```

FastAPI будет центральной точкой системы:

- сайт будет получать и отправлять данные через backend API;
- Telegram-бот будет регистрировать пользователей и создавать задачи;
- серверный worker будет получать задачи и отправлять результаты;
- PostgreSQL будет единым хранилищем данных;
- VPN-панель будет отвечать за создание клиентов и подписок.

Предполагаемые группы API-маршрутов:

```text
/api/auth/*       — регистрация и вход
/api/tasks/*      — работа с задачами
/api/admin/*      — функции администратора
/api/internal/*   — взаимодействие бота и серверных worker'ов
```

Это будет одно FastAPI-приложение, а не несколько отдельных backend API.

### Работа с базой данных

Для работы с PostgreSQL будет использоваться SQLAlchemy 2.0.

Основная работа с базой данных будет выполняться через модели, сессии и запросы
SQLAlchemy. Необходимый драйвер подключения к PostgreSQL будет выбран при
реализации backend и добавлен в список зависимостей проекта.

На начальном этапе таблицы будут создаваться средствами SQLAlchemy.
Дополнительные инструменты управления структурой базы могут быть добавлены
позже, если в них появится практическая необходимость.

Конфигурация приложения пока будет загружаться через `python-dotenv` и
`os.getenv()`.

### Frontend

Frontend не является основной учебной частью проекта и будет разрабатываться преимущественно с помощью нейросетей.

В дальнейшем frontend может быть изменён или полностью заменён. Backend не должен зависеть от конкретной реализации интерфейса.

## Структура проекта

```text
Telegram_bot/
├── Bot.py                    # Telegram-бот
├── panel.py                  # клиент API VPN-панели
├── main.py                   # запуск бота и мониторинга
├── requirements.txt          # зависимости бота
├── .env.example              # пример конфигурации
├── logs.log                  # рабочий файл логов, не хранится в Git
│
├── data/
│   ├── inbound_ids.json      # временный кеш inbound ID
│   ├── server_options.json   # временный кеш конфигурации
│   └── users.json            # временное хранилище пользователей
│
├── front/
│   ├── app.py                # FastAPI-приложение текущего сайта
│   ├── routers/
│   │   └── pages.py          # маршруты страниц
│   ├── templates/            # Jinja2-шаблоны
│   ├── static/               # CSS и статические файлы
│   ├── data/
│   │   └── tasks.json        # временные мок-данные
│   └── requirements.txt      # зависимости текущего сайта
│
└── learning/                 # учебные примеры
```

JSON-файлы используются временно. По мере разработки пользователи, VPN-подписки и задачи будут перенесены в PostgreSQL.

Файл `logs.log` автоматически создаётся Loguru при запуске приложения и не хранится в Git.

## Конфигурация

Создайте `.env` на основе `.env.example`:

```env
API_TOKEN_TG=telegram_bot_token
API_TOKEN_PANEL=vpn_panel_token
base_url=https://panel.example.com/api/
path_sub=https://subscription.example.com/
```

Описание переменных:

| Переменная | Назначение |
|---|---|
| `API_TOKEN_TG` | токен Telegram-бота |
| `API_TOKEN_PANEL` | токен доступа к VPN-панели |
| `base_url` | базовый URL API VPN-панели |
| `path_sub` | базовый URL VPN-подписки |

Файл `.env` содержит секретные данные и не должен добавляться в Git.

Сейчас страницы используют временные данные из `front/data/tasks.json`.
